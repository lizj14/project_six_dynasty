## 三、命中率

- 总计划步数 28，**重规划 2 次**（东晋1、东晋3 各 1 次），命中率 **92.9%**。
- 两次重规划都是**子 agent 的事实错误**，不是执行器 bug：
  1. 东晋1 计划「进军谯」，但谯已被队友东晋2 占据（没注意队友动作）。
  2. 东晋3 计划「占据长安」，但进军长安实际花 5 军力（它按 4 算），军力不足。

## 四、执行器层发现并修复的 bug（共 4 处）

1. **等价多义**：打「士卒」匹配 5 张一模一样的士卒，误判多义 → 加「等价匹配」任选其一。
2. **类型别名**：计划写 `activate`，引擎是 `activate_effect` → 加别名映射。
3. **子决策被静默吞掉**（最严重）：activate/play_card 效果触发的「转化目标/存档目标」等子决策，最初被 `select_target` 静默吞掉（读了下一计划步、返回 None）。加了 `pending_target/pending_choice/pending_discard` 队列，把 plan 里的 `target/choice/discard` 字段接到对应子决策接口。
4. **弃牌顺序**：子 agent 初版漏了【新手牌】通配符 → 强化 prompt 要求 + 代码兜底。

## 五、关键结论

1. **回合级规划可行，命中率 ~93%**：子 agent 能一次性规划整回合（含军力账、支付牌、子决策目标），大部分步骤一次命中。
2. **子 agent 的事实错误是主要风险**：两次重规划都源于「对局面/费用的误判」（队友已占某地、进军费用算错）。这印证了「规划一次 vs 逐步看真实状态」的质量差距——需要靠「失败重规划」兜底。
3. **子决策（转化/存档/二选一）是回合级规划最棘手的部分**：必须让 plan 显式携带 `target/choice/discard` 字段，否则执行器会静默错位。已修。
4. **速度仍受「现场读代码」拖累**：东晋1/东晋3 的初设各读了 17~24 次工具、花了 31/16 分钟。快模式（喂规则要点）仍是提速方向。
