# 回合级规划测试 · 问题分析

> seed=20260819 · 快模式 + 回合级规划（每回合一次性规划整回合）
> 进度：初设 4 席 ✅ · 北方第 1 回合 ✅（3 次重规划 + 1 次回退）· 东晋1 第 1 回合 ⚠️（规划完成，执行卡死）
> 结论：**回合级规划的「规划」质量高，但「执行层基建」未到位，暴露了 5 类问题。**

---

## 问题 1（引擎 bug）：choice 事件牌「苏峻」效果不结算

**现象**：北方 plan 第 1 步「play_card 苏峻」执行后，苏峻的「选择一项：付3vp得5军力 / 付3军力存档」**choice 根本没触发**——军力没 +5、VP 没 -3，苏峻直接被弃掉。

**根因**（两处编译问题，见 `versions/v1.0/cards/cards_compiled.json:6105`）：

1. `parsed_effect.blocks[0].ability_type = "strategy_action"` —— 但苏峻是 **event 牌**（`card_type: "event"`）。事件牌被打成「策略行动」，走错结算路径。
2. `choice_options[0]` 只有 `gain_military 5`，**丢了「支付3vp」**——text 原文是「支付3vp，然后获得5军力」，但解析后选项1只剩 `gain_military`，`pay_vp 3` 丢失。

**影响**：北方子 agent 以为军力 5+5=10，实际仍是 5，后续整回合军力预算全部错位。

**建议排查**：`engine/cards/effect_parser.py` 里对「选择一项：支付X，然后Y」的 choice 解析，以及 event 牌 `ability_type` 的标记逻辑（同类问题可能不止苏峻一张，如「谯纵」等 choice 事件牌）。

## 问题 2：额度误判的连锁反应

**现象**：苏峻「打出」本身**占用了手牌行动额度**（虽然效果没结算）。子 agent 重规划时误以为额度还在，规划了「求田问舍」（公共行动 = 手牌行动），执行时 no_match。

**根因**：引擎把「打出」和「结算」分开记——苏峻打出了（额度占用），但效果没结算（bug）。子 agent 只看到「效果没结算」，没意识到「额度已占用」。

**影响**：北方第 1 回合经历了「求田问舍 no_match → 回传重规划」的额外一轮。

---

## 问题 3：语义协议不被遵循

**现象**：东晋1 子 agent 的 plan 里出现多处字段错误：

| 子 agent 写的 | 应为 | 位置 |
|---|---|---|
| `{"type":"court_action","name":"士卒"}` | `"card"` | plan 第 1 步 |
| `{"type":"play_card","name":"陶渊明"}` | `"card"` | plan 第 2 步 |
| `{"type":"recruit","payment":["杨佺期"]}` | `"card"` | plan 第 3/5 步 |
| `{"type":"march","target":"中原"}` | 具体地点名（如雍丘/谯） | plan 第 4/6 步 |

**根因**：`plan_prompt.md` 的硬性规则里写了字段规范，但子 agent 在「一次性输出整回合 plan」时没有严格遵守，且把「区域」当成了「地点」。

**影响**：这些字段错误会导致执行时 no_match（匹配不上），或匹配到错误的行动。

**建议**：语义协议需要**机器校验 + 明确报错**（而不是静默 no_match），最好在 `plan_prompt` 里加「输出示例必须与示例格式逐字段一致」的强约束，或在裁判侧加一层 plan 字段校验。

---

## 问题 4：无回退机制

**现象**：`move` 命令只追加到 moves.jsonl，不删除。某步 no_match 后，错误步骤残留，导致 step 一直卡在错误步骤。本次只能手动 `head -10` 回退。

**根因**：`play_claude.py` 缺一个「回退到最后一步正确状态」的原语。

**建议**：加一个 `undo`（或 `rollback`）命令，删除 moves.jsonl 末尾的错误步骤；或在 move 时校验语义匹配、匹配不上就不落盘（move 时预检，而不是 step 时才 no_match）。

---

## 问题 5：回放错位（东晋1 执行卡死的直接原因）

**现象**：north 的 `activate 崔宏`（语义）回放时 no_match（北方此刻 available_actions 里没有「激活崔宏」），导致 cursor 错位，最终把 `jin_1` 的 move 当成 `north` 的决策读了，状态混乱。

**根因**：`activate` 语义匹配（`activate → activate_effect`）在某些状态下匹配不到，而引擎的 cursor 是全局顺序推进，一旦某步 no_match 又没正确停下，后续所有 move 都错位。

**建议**：理清 `activate`（以及所有语义 type）与 `available_actions` 的匹配边界；no_match 时必须**精确停在出错的那一步**并 dump，不能让 cursor 继续漂移。

## 结论与下一步

1. **回合级规划的价值已初步验证**：北方子 agent 的整回合 plan + reasoning 质量很高（军力预算、候选方案对比、死牌变现、幕僚引擎建设都想得很清楚），且「一次规划管一回合」的调用次数显著低于逐步决策。
2. **但执行层必须先补课**：语义协议校验、回退原语、choice 事件牌 bug、语义匹配边界，这四件事不修，后面每个席位都会反复撞同一批坑。
3. 建议顺序：**先修苏峻 choice bug + 加回退原语 + 加 plan 字段校验 → 再重跑回合级规划**。
