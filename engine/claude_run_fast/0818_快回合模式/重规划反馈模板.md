# 回合级规划 · 重规划反馈模板

> 当子 agent 的整回合 plan 执行失败（no_match / 额度冲突 / 状态变化），裁判用此模板回传「当前状态」，让子 agent 基于**真实状态**重规划，而不是靠推理。
> `{...}` 为动态填充，字段来源：`claude_state.json` 的 `viewport.private`。

---

【重规划请求】

你的 plan 第 {N} 步「{失败语义行动}」执行失败，原因：{reason}（no_match / 额度已用 / 地点被占 / 军力不足）。

## 已执行（前 {N-1} 步已成功）
{executed_steps}

## 当前状态
- VP {vp} · 军力 {military} · 威望 {prestige} · 功绩 {contribution}
- 手牌 {count} 张：{hand}
- 幕僚：{staff}
- 占据 {count} 地点：{locations}

## 当前额度状态（明确给定，不要自己推理）
- 手牌行动：{hand_action_used}
- 牌组行动：{court_action_used}
- 摸牌（快速）：{drawn_quick}
- 加固（快速）：{fortified_quick}
- 已激活的幕僚/英雄：{activated_cards}

## 剩余可执行（供重规划参考）
{remaining_actions}

---

请基于以上重规划剩余回合，输出新的 JSON（reasoning + discard_order + plan）。

## 字段来源对照

| 模板字段 | claude_state.json 的 viewport.private 字段 |
|---|---|
| hand_action_used | `can_take_hand_action` == false → 「已用」 |
| court_action_used | `can_take_court_action` == false → 「已用」 |
| drawn_quick | `has_drawn_quick` == true → 「已用」 |
| fortified_quick | `has_fortified_quick` == true → 「已用」 |
| activated_cards | `activated_card_ids`（对应幕僚/英雄名） |

## 为什么这个模板能解决「额度误判」

苏峻 bug 的教训：子 agent 靠「效果没结算 = 没打出 = 额度还在」的推理链，误判了手牌行动额度。这个模板把「额度状态」作为**明确输入**（从 viewport 直接读，不经过子 agent 的推理），彻底消除这一类误判。

即使某张牌「打出」和「结算」分离（如苏峻），`can_take_hand_action` 也会反映「打出」已经占用了额度，子 agent 看到「手牌行动：已用」就不会再规划求田问舍。
