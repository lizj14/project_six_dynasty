# Crafter 研究全景：从基准到超越人类

> Crafter (Hafner, 2021) 是一个 2D 开放世界生存游戏 RL 基准，灵感来源于 Minecraft。自发布以来，围绕它形成了多条独立的研究线索。本文档系统性地梳理这些工作。

---

## 零、缘起：为什么需要 Crafter？

Hafner (Google Brain / UofT) 在 2021 年 NeurIPS 提出了 Crafter。核心动机是填补 AI 评估的空白：

```
Atari (57 个游戏)    →  太简单，2000 GPU 天才能跑完一轮
      ↕  空白地带：需要多任务 + 深度探索 + 长期规划，但又要跑得快
Minecraft (MineRL)   →  太复杂，3D 渲染 + 海量交互，学术界无法规模化
```

**Crafter 的设计理念**：用一个环境测试尽可能多的能力。22 个成就组成深度为 7 的科技树，包括采集、建造、制作、战斗、探索等——但用 64×64 的 2D 画面和 17 个离散动作，一台普通 PC 几小时就能跑完 1M 步训练。

评估指标：**Crafter Score** = 22 个成就解锁率的几何平均 $S = \exp(\frac{1}{N}\sum \ln(1+s_i)) - 1$，对困难成就的进步更敏感。

## 一、RL 基线建立与调优（2021-2022）

### 1.1 原论文基线 (Hafner, 2021)

| 方法 | Score | 性质 |
|------|-------|------|
| Human Experts | 50.5% | 人类上限 |
| DreamerV2 | 10.0% | 模型-based |
| PPO | 4.6% | 模型-free |
| Rainbow | 4.3% | 模型-free |
| Random | 1.6% | 下界 |

### 1.2 强基线重评估 (Stanić et al., ICML 2022 Workshop)

**核心贡献**：发现原论文的 PPO 基线严重被低估——经过合理的超参调优和架构改进后，PPO 可以达到远超原论文的水平。

关键发现：
- **SPCNN**（尺寸保持 CNN，134M 参数）远超标准 CNN（1M 参数）——Score 从 4.6 → **11.6**
- **LSTM + SPCNN** = **12.1%**，成为当时最强纯 RL 基线
- 去掉背包显示：Score 下降 ~35% → 部分可观测性下的记忆至关重要

同时引入了 **CrafterOOD**：15 个分布外泛化测试环境，包括外观变换和物体数量变换。所有 CNN/LSTM 基线全部失败，只有**物体中心（Object-Centric）架构**能泛化。

**解决的问题**：RL 在 Crafter 上的"真实天花板"到底在哪里？答案是原来的 PPO 基线远未触顶。

## 二、世界模型路线（2021-2025）

这是 Crafter 上最成功的范式——构建环境的世界模型，在隐空间中规划。

### 2.1 Dreamer 系列

| 版本 | 年 | Score | 核心创新 |
|------|-----|-------|---------|
| DreamerV2 | 2021 | 10.0% | RSSM (Recurrent State-Space Model)，离散隐变量 |
| DreamerV3 | 2023 | 14.5% | 统一超参数，无需调参即可跨域迁移，201M 参数 |

DreamerV3 的意义不在于 Crafter 上的绝对分数，而在于**同一套代码和超参**就能在 Crafter、Atari、DMControl 等多个领域有效——但它仍有 201M 参数，训练成本不低。

### 2.2 Δ-IRIS (Micheli et al., ICML 2024)

**核心创新**：上下文感知的 tokenization。传统世界模型将每一帧独立编码为离散 token，Δ-IRIS 只编码帧间**随机增量（stochastic delta）**——即"发生了什么变化"。

效果：token 数量大幅减少，transformer 推理速度提升 **~200 倍**。10M 帧后解锁 17/22 成就，Score = 16.1，超越 DreamerV3。

**解决的问题**：世界模型的 token 效率——没必要每帧重新编码整个画面，只编码"变化"就够了。

### 2.3 EMERALD (Burchi & Timofte, ICML 2025) 🏆

**核心创新**：空间隐状态 + MaskGIT 并行解码。不做自回归逐 token 生成，而是一次性并行预测未来状态。

**里程碑成就**：
- **首个超越人类专家的 Crafter Agent**（10M 步内）
- **解锁全部 22 个成就**
- 27 FPS @ RTX 3090

**解决的问题**：世界模型的生成效率——自回归生成太慢，并行解码才是正解。

### 世界模型路线总结

```
DreamerV2 (2021)     RSSM + 离散隐变量                Score: 10.0%
    ↓
DreamerV3 (2023)     统一超参 + 大规模                 Score: 14.5%
    ↓
Δ-IRIS (2024)        增量 tokenization + 提速 200×      Score: 16.1 (17/22)
    ↓
EMERALD (2025)       空间隐状态 + MaskGIT 并行解码      Score: >Human (22/22)
```

## 三、探索方法路线（2021-2025）

Crafter 的奖励极其稀疏——只在**首次**解锁某个成就时给 +1。如何在不依赖奖励的情况下探索？

| 方法 | 年 | 核心思想 | 效果 |
|------|-----|---------|------|
| RND | 2018 | 预测网络误差作为内在奖励 | Score: 2.0% (≈随机) |
| Plan2Explore | 2020 | 自监督世界模型驱动的探索 | Score: 2.1% (≈随机) |
| **Curious Replay** | 2023 | 结合 count-based 新颖性 + 世界模型误差，优先回放"既新鲜又意外"的经验 | Score 相对 DreamerV3 提升 **1.33×** |
| **CBET** | 2025 | 基于状态变化稀有度的内在动机迁移 | 进一步提升 DreamerV3 在 Crafter 上的收益 |

**关键发现**：纯内在动机方法（RND, Plan2Explore）在 Crafter 上效果极差，因为成就导向的行为需要**定向探索**而非随机漫游。Curious Replay 表明正确的方向是**引导已有模型去探索**，而非从零用好奇心驱动。

**解决的问题**：如何在巨大且稀疏奖励的空间中找到 22 个成就？纯好奇心不够，需要"定向好奇心"。

## 四、LLM 方法路线（2023-2024）

这是与 SPRING 直接相关的路线——LLM 以不同方式介入 Crafter。

### 4.1 ELLM (Du et al., 2023)

- **角色**：LLM 作为**奖励生成器**
- **做法**：Codex 为 RL Agent 生成辅助奖励信号，帮助它在 5M 步预训练中学习
- **代价**：**500 万次 LLM 调用**
- **结果**：Reward = 6.0

**解决的问题**：稀疏奖励问题——用 LLM 的语言理解能力生成更密集的奖励信号。

### 4.2 SPRING (Wu et al., NeurIPS 2023) ← 我们深度分析过

- **角色**：LLM 作为**Agent 本身**
- **做法**：GPT-4 读 Crafter 论文 + QA-DAG 推理 → 每步选动作
- **代价**：约 2,700 次 LLM 调用/局，~$270/局
- **结果**：Score = **27.3%**（0 训练步，超越所有 1M 步 RL 基线）

**解决的问题**：能不能完全不训练，只靠"读说明书"就玩游戏？能。

### 4.3 EnvGen (Zala et al., COLM 2024) 🏆

- **角色**：LLM 作为**训练环境生成器**
- **做法**：GPT-4 分析 Agent 的弱项 → 生成针对性的训练环境（地形、物品稀有度、初始装备）→ 小 RL Agent 在环境中训练 → 4 轮迭代循环
- **代价**：**仅 4 次 LLM 调用**，总成本 < $1
- **结果**：
  - PPO + EnvGen: Score = **32.2%**
  - AD + EnvGen: Score = **35.3%**（LLM 方法中最高）

**核心洞察**：LLM 不擅长做 Agent（SPRING 的 $270/局 vs 32.2%），但**极其擅长做教师**——分析弱项、设计针对性训练。4 次调用 > 2700 次调用。

**解决的问题**：LLM 到底应该在游戏 AI 中扮演什么角色？不是替代 RL，而是**指导 RL 训练**。

### LLM 路线对比

| 方法 | LLM 角色 | LLM 调用量 | 成本 | Score |
|------|---------|-----------|------|-------|
| ELLM | 奖励生成器 | 5M | 极高 | Reward 6.0 |
| SPRING | Agent 本身 | 2,700/局 | ~$270/局 | 27.3% |
| **EnvGen** | **训练环境生成器** | **4** | **<$1** | **35.3%** |

趋势线非常清晰：**在 LLM 方法中，LLM 离执行层越远、离训练设计层越近，效果越好、成本越低。**

## 五、层次化 / 成就结构方法（2023）

### Achievement Distillation (Moon et al., NeurIPS 2023)

- **核心创新**：利用成就的层次结构作为自监督信号
- **两个辅助目标**：
  1. **轨迹内成就预测**：最大化 state-action 与下一个解锁成就的隐空间相似度
  2. **跨轨迹成就匹配**：用最优传输对齐不同局中的相同成就
- **结果**：Score = **21.8%**（仅 4M 参数，约为 DreamerV3 的 4%），1M 步内解锁全部 22 成就
- **+EnvGen 后**：Score = **35.3%**

**解决的问题**：RL 不知道成就之间存在依赖关系（必须先有木镐才能采石）。成就蒸馏让 Agent 自动发现这个层次结构，从而更高效地探索。

## 六、基准扩展路线（2022-2025）

随着研究深入，原版 Crafter 的局限性逐渐暴露，催生了一系列扩展。

### 6.1 CrafterOOD (Stanić et al., 2022)

- 15 个分布外泛化测试环境
- 类型：外观变化（换纹理）+ 数量变化（改变物体密度）
- 所有标准 CNN/LSTM Agent 全部失败 → 催生了物体中心架构的研究

### 6.2 Craftax-Classic (Matthews et al., 2024)

- Crafter 的 **JAX 重写版**，与原版机制尽可能一致
- 速度提升 **250 倍**
- PPO 跑 1B 步 → **不到 1 小时**在单 GPU 上完成 → 基本"解决"了原版 Crafter
- 支持符号化观测（比像素观测再快 10 倍）

### 6.3 Craftax (Matthews et al., 2024)

- 在 Crafter 基础上的**大幅扩展**，加入 NetHack 元素：
  - 9 层程序化生成的地牢（洞穴、火/冰层、Boss 层）
  - 19 种生物 + 战斗系统大改（物理/火/冰伤害、弓箭、法术、护甲）
  - 药水效果每局随机排列（测试 in-context 学习）
  - 属性系统（敏捷/力量/智力）+ 经验升级
- 现有方法（探索、环境设计）几乎无进展 → **新的挑战前沿**

### 6.4 CrafText (Volovikova et al., 2025)

- 基于 Craftax 的多模态指令跟随基准
- 3,924 条指令，3,423 个独特词汇

### 6.5 CrafterDojo (Park et al., 2025)

- 集成基础模型：CrafterVPT（专家行为）、CrafterCLIP（视觉-语言对齐）、CrafterSteve-1（指令跟随）

## 七、全景总结

### 按路线分类

| 路线 | 代表工作 | 核心问题 | 最高成就 |
|------|---------|---------|---------|
| **RL 基线** | Stanić et al. (2022) | PPO 的真实上限是多少？ | Score: 12.1% (LSTM-SPCNN) |
| **世界模型** | DreamerV3 → Δ-IRIS → EMERALD | 如何高效建模环境动态？ | **22/22 成就，超越人类** |
| **探索方法** | Curious Replay, CBET | 稀疏奖励下如何探索？ | 1.33× 提升 vs 均匀回放 |
| **LLM 方法** | ELLM → SPRING → EnvGen | LLM 在游戏中该扮演什么角色？ | Score: 35.3% (AD+EnvGen) |
| **层次化** | Achievement Distillation | 如何利用成就结构？ | Score: 21.8% (4M 参数) |
| **基准扩展** | CrafterOOD → Craftax → CrafText | 原版天花板后该往哪走？ | 250× 提速 + 9 层地牢 + 指令跟随 |

### 关键转折点

1. **2022**: Stanić 证明 PPO 被严重低估 → 整个领域的基线需要重新校准
2. **2023**: SPRING 证明 LLM 可以不训练直接玩 → 范式冲击
3. **2024**: EnvGen 证明"LLM 当老师" > "LLM 当玩家" → 方向纠正；Craftax 证明原版已被"解决" → 需要新基准；Δ-IRIS 证明 token 效率是可优化维度
4. **2025**: EMERALD 超越人类专家（22/22 成就）→ 原版 Crafter 作为一个"挑战"的时代结束

### Crafter 研究的三条哲学线索

```
线索一：如何让 Agent 自己学会玩？
        RL → 世界模型 → 探索方法 → 层次化 → EMERALD (超越人类)

线索二：LLM 在其中该扮演什么角色？
        当玩家(SPRING) → 当奖励(ELLM) → 当教练(EnvGen) → 最优解

线索三：原版天花板到了，然后呢？
        CrafterOOD → Craftax → CrafText → 更难的泛化 + 更快的迭代
```

### 对六朝项目的启示

Crafter 的研究史提供了一个"AI 攻克一个游戏"的完整标本：

| Crafter 阶段 | 对应六朝启示 |
|-------------|------------|
| 先建强 RL 基线 | 六朝需要先有一个经过充分调优的规则/RL 基线，知道"纯工程"能走多远 |
| 世界模型路线 | 六朝作为卡牌博弈，是否需要环境模型？或者规则本身已经是完美的世界模型？ |
| LLM 方法演化 | **关键启示**：LLM 做"教练"（分析弱点、生成训练数据）可能比做"玩家"更有效 |
| 基准扩展 | 六朝需要多个难度/泛化维度的测试集，不能只有一个"胜率"指标 |
