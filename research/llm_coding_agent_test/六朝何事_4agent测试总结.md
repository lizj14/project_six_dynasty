# 六朝何事 · 4 Agent 对战测试 工作总结

> 本目录下 `README.md` 是「领土/Dominion」的前置实验，本文是「六朝何事」的正式测试总结。
> 核心产出：文件驱动引擎 `play_claude.py`、3 个独立上下文的 coding 子 agent、每席决策日志、5 条规则/代码不一致修复。

## 0. 一句话概述

围绕自研四人半合作桌游「六朝何事」（1 北方 vs 3 东晋，含手牌/秘密目标等隐藏信息），用「文件驱动 + 确定性回放」的方式，让 **3 个独立上下文的 coding 子 agent（北方、东晋2、东晋3）+ 1 名人类玩家（东晋1）** 完整打完第 1 回合（含初设），停在第 2 回合开始。验证了隐藏信息隔离、每席决策日志、「coding agent 读代码打桌游」的可行性，同时量化了速度成本、并暴露了子 agent 的事实性/下标错误。

---

## 1. 背景与目标

「六朝何事」复杂度远高于领土：4 人、不对称、半合作（三家东晋既合作北伐又竞争个人 VP）、点线区控地图 + DBG + 文化 + 威望/功绩系数。核心研究问题是：

1. **coding agent（读代码）能否玩这个高复杂度游戏？** 规则遵循度是否高于「喂规则摘要的裸 LLM」。
2. **隐藏信息如何隔离？** 三个子 agent 各自只能看到自己座位的视窗。
3. **每席的决策思考过程如何留痕？** 供事后审计「它当时知道什么、怎么想的」。
4. **规则书与代码是否一致？** 边打边核对。

## 2. 方法（架构）

### 2.1 文件驱动 + 确定性回放

仿照领土 `llm_game.py` 的「状态 = f(seed, moves) 纯函数」：

```
python engine/play_claude.py new --seed 20260815 --human jin_1   # 开局
python engine/play_claude.py step                                  # 回放到下一个决策点，dump 视窗
python engine/play_claude.py move '<决策JSON>'                    # 记录一步决策
python engine/play_claude.py status                                # 看进度
```

每一步都从 seed + `moves.jsonl` 完整回放，可随时回退重打。

### 2.2 三个隔离子 agent + 一个人类

| 席位 | 控制者 | 英雄 |
|------|--------|------|
| 北方 | 子 agent（general-purpose，全仓库读权限） | 苻坚 |
| 东晋1 | 人类玩家（本测试的操作者） | 祖逖 |
| 东晋2 | 子 agent | 桓温 |
| 东晋3 | 子 agent | 谢安 |

每个子 agent 用 Agent 工具 spawn、SendMessage 续接，**上下文独立（硬隔离）**；各自可 Read/Grep 规则书、卡表、引擎源码。

### 2.3 隐藏信息隔离

`SnapshotViewport(viewer_id=座位)` 按席位过滤：每个子 agent 收到的 dump **只含自己的手牌 + 公开信息**，别家手牌/秘密目标在结构上就不存在。

### 2.4 每席决策日志

每次决策，子 agent 输出 `【思考】+【决策】`，裁判逐条原样追加到该席的日志文件，供审计。

---

## 3. 实现

- **`engine/play_claude.py`**：文件驱动（new/step/move/status/show），含 `ReplayController`（全局决策队列）+ `ReplayAgent`（回放/缺决策时 dump 并抛 `NeedsDecision`）。
- **子 agent 编排**：主 agent 当裁判——`step` 拿当前座位视窗 → SendMessage 转发给对应子 agent → 收回 `【决策】` → `move` 落子 → 记日志。人类座位改为在对话里呈现、等人工报决策。
- **每席日志**：`engine/claude_run/reasoning/{north,jin_1,jin_2,jin_3}.md`。
- **测试日志**：`GameLogger` 生成完整逐行动日志。

## 4. 实验过程与结果

### 4.1 对局配置

- seed = 20260815，人类 = 东晋1（祖逖）
- 共记录 **55 步决策**（含初设 + 各英雄登场效果 + 第 1 回合全部行动）

### 4.2 第 1 回合结果（停在第 2 回合开始）

| 席位 | VP | 控制区域 | 占据地点 |
|------|----|---------|---------|
| 北方 | 12 | 关中、中原 | 安定/天水/长安/弘农/洛阳/雍丘/东平/平阳 |
| 东晋1（人） | 5 | 巴蜀 | 巴郡、蜀郡 |
| 东晋2 | 2 | 荆襄 | 襄阳/南郡/宛城/上洛 |
| 东晋3 | 3 | 山西、淮南 | 太原/上党★/寿春/广陵 |
| 司马家 | 8 | 西凉、江南 | 张掖/姑臧/巴东/武昌/浔阳/建康/京口/吴/会稽/合肥 |

子 agent 的决策质量总体合理：北方率先铺关中+中原（最高 VP 区）、东晋2 抢荆襄、东晋3 用「流民帅」远程转化 + 进军上党拿下山西区控并锁定公开目标「表里山河」。

## 5. 关键发现与问题

### 5.1 速度：子 agent 纯算力约 7 小时

| 席位 | 决策次数 | 总耗时 |
|------|---------|--------|
| 北方 | 17 | ~330 分钟（5.5 小时） |
| 东晋2 | 12 | ~55 分钟 |
| 东晋3 | 9 | ~31 分钟 |
| **合计** | 38 | **~417 分钟（≈7 小时）** |

- 北方最慢：先行者要现场读代码摸索规则，单步 15~30 分钟、10+ 次 tool 调用。
- 决策耗时**由「决策复杂度」驱动，而非「越玩越快」**——东晋2 中间几步（打谢艾 6.7min、激活谢艾 8.7min、征募 9min）反而比开头慢。
- **隔离未破**：三个子 agent 上下文独立，速度差异来自「先行者摸索成本 + 裁判 prompt 越来越厚」，不是 agent 之间串信息。

### 5.2 子 agent 的事实性错误

- 东晋3 以为「平阳」是中立、想用流民帅远程转化，实际平阳已被北方控制；引擎的目标过滤拦下后，它改选太原。**地图状态的认知错误**是 LLM 打桌游的典型问题。

### 5.3 子 agent 的下标错误

- 东晋2 想「征募弃凉州大马」，写 `index 0`，但 0 其实是摸牌（凉州大马是 index 1）。裁判按它的意图纠正了。**数字下标协议对 LLM 有出错风险**，建议改成语义化选择。

### 5.4 支付牌无法按 agent 意愿指定

- 引擎 `get_available_hand_actions` 只自动填充支付（弃手牌顺序前 N 张），子 agent 想弃的牌无法指定。已给驱动加「payment 可指定」补丁（人类打桓宣弃崔宏已用到），但子 agent 侧尚未接入。

### 5.5 会话重启导致子 agent 中断

- 中途因改权限重启了会话，东晋3 的原始子 agent 被停掉，需重新 spawn（丢了一次初设决策）。持久化子 agent 的上下文跨会话恢复是待解决的问题。

## 6. 修复的规则/代码不一致（5 条，见 `discrepancies.md`）

| # | 严重度 | 问题 | 修复 |
|---|-------|------|------|
| 1 | 高 | 规则书 §3.2 区域列表过时（8 区域「河南」） | 改为 12 区域「中原」 |
| 2 | 中 | `viewport/utils.py` 弘农误标关中 | 改回中原 |
| 3 | 中 | 目标牌条件加载失效（version.py 读错字段） | 改用 `GOAL_DEFINITIONS` 唯一真源 |
| 4 | 低 | `enums.py` 区域注释过时 | 修正 |
| 5 | 低 | `board_info.md` 地名不统一（关外/邺/成都） | 修正 |

---

## 7. 下一步

1. **快模式**：把「子 agent 现场读代码」换成「裁判提炼规则要点一次性喂给子 agent」，单步有望压到 1 分钟以内（验证「LLM 能不能玩」而非「LLM 读代码玩」）。
2. **支付指定接入子 agent**：让子 agent 的决策也能带 `payment` 字段。
3. **语义化决策协议**：用「打「凉州大马」」替代裸下标，降低下标错误率。
4. **多局 + 异质 agent**：跑多 seed，观察东晋三家半合作/内斗的涌现。
